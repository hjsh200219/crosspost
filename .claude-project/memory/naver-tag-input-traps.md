네이버 블로그 SE-ONE 발행 레이어의 태그 입력(`input[class*="tag_input__"]`, placeholder "태그 입력 (최대 30개)")에는 **조용히 실패하는 함정이 두 개** 있다. 2026-07-25 실제 에디터로 확인했다.

1. **공백이 태그 구분자로 동작한다.** `AI 법률 상담`을 한 덩어리로 치고 Enter를 눌러도 저장 결과는 `AI`,`법률`,`상담` 3개다. 게다가 태그 수가 불어나면서 뒤쪽 키워드가 유실된다(6개 입력 → 9개 저장 + 마지막 2개 소실).

2. **허용되지 않는 문자는 입력이 거부되면서 그 뒤 태그까지 삼킨다.** `yt-dlp`를 넣자 그것도, 바로 다음 `vibecoding`도 저장되지 않았다(6개 입력 → 4개 저장). 거부된 문자열이 입력창에 남아 다음 입력과 뒤엉키는 것으로 보인다.

**대응**: `toTags()`가 `[^가-힣ㄱ-ㅎㅏ-ㅣa-zA-Z0-9]`를 전부 제거한다. 각 Enter 후 `input.inputValue()`가 비어 있지 않으면 `fill('')`로 잔류분을 지운다.

**검증이 핵심이다** — 필터만으로는 성공을 보장 못 한다:
- 확정 칩 수: `[class*="tag_area"] span[class*="text__"]` 개수를 세어 입력 수와 대조. 불일치면 크게 경고
- 발행 후 서버 확인: `blog.naver.com/BlogTagListInfo.naver?blogId=<id>&logNoList=<logNo>&logType=mylog` — `tagName`이 URL 인코딩된 쉼표 구분 문자열

**기존 태그 제거**는 빈 입력창에서 Backspace 반복(칩 수가 안 줄면 중단해 무한루프 방지). 이게 없으면 재발행마다 태그가 누적된다.

**Why:** 두 함정 다 예외를 던지지 않아서 로그만 보면 성공으로 보인다. 실제로 첫 백필 시도가 6개 입력 → 9개 쪼개짐으로 조용히 잘못 저장됐다.

**How to apply:** 태그를 다루는 코드는 반드시 (1) 한글·영숫자만 남기고 (2) 확정 칩 수를 대조하고 (3) 발행 후 서버 API로 재확인할 것. 공백 제거는 손실이 아니다 — 네이버 검색 수요 자체가 붙여쓴 형태에 몰려 있다(키워드도구 실측 `바이브코딩` 월 34,900).
