Instagram(8번째 채널, 2026-07-27)은 다른 채널과 **전제가 다르다**.

- **텍스트 전용 게시가 없다.** 이미지가 필수라 텍스트 폴백이 존재하지 않는다 → 미디어가 없으면 조용히 넘어가지 않고 큰 소리로 실패해야 한다.
- **API가 바이너리 업로드를 안 받는다.** Meta가 `image_url`/`video_url`을 **공개 URL에서 페치**한다 → 배포용 플러그인에서는 사용자에게 **호스팅 전제**(`CROSSPOST_MEDIA_BASE_URL`)가 생긴다. 이게 이 채널만 셋업이 무거운 이유다.
- **발행 후 되돌릴 수 없다.** 미디어 교체 불가, 캡션도 API가 받아 놓고 무시하는 일이 잦다(그래서 `--edit`은 되읽어 확인하고 다르면 실패).

## 원본 카드 생성기를 그대로 옮기지 않은 이유

원본은 특정 브랜드 디자인 시스템과 자체 토픽 분류에 묶여 있다. 공개 플러그인에 그대로 실으면 **남의 브랜드로 카드가 나간다.** 그래서 엔지니어링만 가져오고 다시 썼다.

- **테마는 중립 기본값 + `$CROSSPOST_HOME/cards.theme.json` 오버라이드**, 시스템 폰트만. 렌더 시 네트워크 요청이 없어 오프라인에서도 같은 결과가 난다(웹폰트를 받아 쓰면 폰트 로딩 실패가 조용히 레이아웃을 바꾼다).
- **글자 폭 추정표 대신 페이지 안에서 오버플로를 실측**한다(`scrollHeight - clientHeight`). 언어별 폭 계수표는 반드시 현실과 어긋나고, 어긋나는 순간 **잘린 카드가 영구히 발행**된다.
- **규격 술어는 `card-rules.mjs` 한 곳.** 생성기와 게이트가 같은 파일을 import한다 — 두 벌로 두면 반드시 갈라지고, 갈라진 쪽은 강제되지 않는다.
- **카드 초안 JSON은 에이전트가 직접 쓴다.** 원본의 `claude -p` 셸아웃은 플러그인 문맥에서 불필요하다(스킬을 실행하는 주체가 이미 LLM이다).

## 게이트

`check-cards.mjs`가 발행 직전 마지막 기계적 방어선이다 — 스테일 렌더(스펙 5장 vs 파일 4장), 캡션 누락·초과, `CROSSPOST_MEDIA_BASE_URL` 미설정. **여기서 못 잡으면 영구다.**

**Why:** 다른 채널은 잘못 나가도 수정·삭제로 회복된다. IG만 회복 경로가 "삭제 후 재발행"뿐이고 URL·지표가 초기화된다.

**How to apply:** IG 관련 기능을 추가할 때는 "발행 후 고칠 수 있나?"를 먼저 묻고, 못 고치면 **발행 전 검증**으로 옮긴다.
